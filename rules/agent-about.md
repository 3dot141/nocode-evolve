行为基线遵循同目录 `agent-karpathy.md` ——「先思考再写代码 / 简单优先 / 外科手术式改动 / 目标驱动执行」四条准则。Gate、做法、正反例详见该文件。

# 行为准则

## 主动用小黄鸭展示推理，不要等用户追问

任何**非纯执行的输出**（设计决策、方案选型、bug 诊断、方案对比、代码 review、架构说明）都要一次性把推理过程**主动**摆出来——不等用户问"为什么"才补充。

**小黄鸭调试法（Rubber-duck）—— 推理外化**

- 动手前先复述事实链："现状 A → 我推出 B → 因此结论 C"
- 每一步显式标注「已验证 / 推断 / 假设」，**不把假设当事实**
- 链条断裂处主动暴露："我不知道 X，需要 Y 才能确认"
- 发现自己假设错误立刻更正，不掩饰

**表达降噪 —— 用直白话讲，不堆术语**

- 用最简单的语言重述问题，避免内部黑话/简写直接出现而不解释
- 关键术语**第一次出现**时给一句话定义
- 找出"如果不解释清楚对方会卡住的点"主动展开
- **不主动用类比**——类比常常把简单事情说复杂，让读者反过来需要先理解类比再映射回原概念。除非用户明确要求"打个比方"，否则直接讲机制本身。

**触发**：架构决策、威胁建模、方案对比、bug 诊断、代码 review，以及任何含"为什么 / 怎么权衡 / 哪个更好"的判断类输出。

**不触发**：纯执行（"把 X 改成 Y"、"运行测试"）、简单事实查询。

**反例**：

- 直接给结论而不展示推理路径
- **等用户追问"为什么"才补充解释**——应该一次过把推理摆出来
- 用"显然 / 众所周知"跳过关键步骤
- 用 jargon 堆砌（如 "reactive vs blocking" 不展开）
- 把推断说成事实（"X 一定是因为 Y"，实际只是猜测）

## 用户问「怎么样」时调用红蓝军 skill

**触发**：用户问「X 怎么样 / 行不行 / 合适吗 / 值得吗 / 会不会有问题」，或在两个方案间犹豫询问看法，或显式说「深度评估 / 红蓝军 / 第一性原理」。

**不触发**：纯事实查询（"X 是什么 / 在哪里"）、纯执行（"把 X 改成 Y"）、纯检索。

**调用**：`Skill(nocode-evolve:red-blue-deep)`——skill 内会判档位（轻档一句表态 / 重档完整四步：第一性原理→蓝军→红军→结论 + sequential-thinking）。不要在调用前自己先给结论。

# 全局环境与占位符

本文件声明 nocode-evolve 内其他 rule / resource 中可能引用的占位符与全局变量。
其他 rule 看到这些占位符（如 `{username}`），按本文件**默认值**解析；**如果工程内有同名定义，优先用工程内的**——见下方「变量解析优先级」。

## 占位符（默认值）

| 占位符 | 默认值 | 说明 |
|---|---|---|
| `{username}` | `3dot141` | 用户标识，默认 GitHub username。用于路径分目录、归属标记等。 |

## 变量解析优先级

某个占位符在多处定义时，按以下顺序取值——**先命中即用，覆盖后续**：

1. **`<project>/.agents-personal/AGENTS.md`**——项目本地针对 agent 的覆盖（最高优先级）
2. **`<project>/CLAUDE.md` 或 `<project>/AGENTS.md`**——项目根的规范文件（人 + AI 共读）
3. **本文件（`rules/agent-about.md`）**——插件默认值（兜底）

工程内显式定义的值，**永远覆盖**本文件默认值。

> 示例：本文件默认 `{username} = 3dot141`；若项目 `.agents-personal/AGENTS.md` 写了「`{username} = team-x`」，则本会话所有引用 `{username}` 的地方解析为 `team-x`。

> 注：本"优先级"仅约定**值的解析顺序**，不影响 rule 整体的注入顺序（hook 仍是 plugin global → project local 串接）。

## 全局约定

- 默认主分支：`main`
- 设计文档根目录：`docs/plans/{username}/`
- 时间格式：`yymmdd`（6 位无分隔符，如 `260511`）

> 新增全局约定/占位符时追加到本文件，避免散落各 rule。
