# Feat closure

Check the current half only. Reopen the responsible function, not an F-number.

## 产品 Gate

- [ ] The real outcome maps to the function tree.
- [ ] One panorama plus a function tree exist. No implementation flowcharts in this half.
- [ ] Explicit non-scope and preserve obligations are recorded.
- [ ] No branch is actually an unseparated bug or independent refactor outcome.

Run the 开发 Gate only after the 产品 confirmation ROUND is closed and development sections exist.

## 开发 Gate

- [ ] The real outcome maps to the function tree.
- [ ] Every function in the tree has a development section, or an explicit n/a reason.
- [ ] Every development section has 流程图, 接口, 伪代码, and 问题.
- [ ] Every applicable competitor insight has provenance and a named impact on the tree or a function.
- [ ] Every domain / data-owner crossing has direction, contract, owner, consistency, authorization, retry / compensation, observation, and verification.
- [ ] Every triggered quality or sensitive risk has an enforceable design and proof objective.
- [ ] Release, migration, compatibility, rollback, and cleanup are closed when applicable.

## 开发 → 产品

- [ ] Every component, contract, store, event, rule, and migration step has a source function, constraint, risk, or preserve obligation.
- [ ] No solution element exists only because it is fashionable, compatible, or fast.
- [ ] Every independent obligation can receive one DES ID and one downstream proof result.

## Type Gate

- [ ] No branch is actually an unseparated bug or independent refactor outcome.
- [ ] Independent acceptable outcomes have their own task Logs.

Any failure reopens the responsible function. Do not compensate by adding prose during writing.
