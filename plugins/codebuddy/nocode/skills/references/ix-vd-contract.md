# IX ↔ VD 分工契约（共享术语单源）

> pd-ix 与 pd-vd 的分工边界与共享术语。两个 skill 各引本文一次，术语定义以本文为单源，两侧不各自维护。
> 动机：「4 态」曾在两个 skill 里指两组不同的状态集（数据态 vs 控件样式态），执行者引用错对象导致砍覆盖——同名不同义必须消除。

## 分层：谁定义什么

```
交互（pd-ix 域）
├── 数据状态    normal / empty / loading / error        逐交互枚举
└── 控件行为    触发 / 规则 / 退出 / 反馈                逐交互定义
                （hover 触发的内容变化、disabled 进入条件、焦点流转都在这）

视觉（pd-vd 域）
└── 控件样式    hover / active / focus-visible / disabled 的外观
                tokens 层组件级统一定义，页面继承，IX 不写
```

**判据一句：该态改变内容或行为 → 交互（pd-ix）；纯样式反馈 → 视觉（pd-vd）。**

按判据劈四个态：

| 态 | IX 管的半边（语义：态的存在与转换） | VD 管的半边（皮肤：态的外观） |
|---|---|---|
| hover | hover 触发内容变化（出浮层 / 出菜单）→ 写进行为规格 | 控件 hover 的统一样式反馈（背景加深、虚线变实线） |
| disabled | 什么时候禁用（必填未完成 → 提交键禁用）→ 行为规格「规则」字段 | 禁用外观（透明度、cursor） |
| focus-visible | 焦点流转逻辑（Tab 顺序、Esc 关浮层后焦点回落） | 焦点圈样式 |
| active | 按下触发的行为差异（长按 vs 单击） | 按下的视觉（下沉 1px） |

## 对应关系：单向可选，不是强制映射

- **IX 有定义的态/行为**：VD 只上皮肤，**不得改语义**（不得改触发条件、退出逻辑、状态转换）。
- **IX 没定义的态**：VD 只能加**纯样式反馈**（普通按钮 hover 变色不需要 IX 条目），**不能就地加行为**——原型阶段发现需要新行为（如 hover 出提示），走 `.ix.md` 的「下游澄清回流」节登记，不许只写在原型代码里。

## 术语表

| 术语 | 定义 | 归属 |
|---|---|---|
| **状态覆盖** | 数据状态 normal / empty / loading / error 的逐交互枚举 | pd-ix |
| **行为规格** | 交互行为的四字段定义：触发 / 规则 / 退出 / 反馈 | pd-ix |
| **控件四态** | hover / active / focus-visible / disabled 的**视觉样式**，tokens 层统一定义 | pd-vd |

## 设计系统三层命名

| 层 | 内容 | 产出阶段 |
|---|---|---|
| **tokens** | 原子层：色板 / 字体角色 / 字号刻度 / 间距 / 圆角 / 阴影 / 控件四态通用规则 | pd-vd Step 3a |
| **components** | 分子层：按钮、卡片、输入框、表格… | pd-vd Step 3b |
| **patterns** | 组织层：页面级布局（= 原型组装） | pd-vd Step 4 |

> 「foundations」一词退役——它在不同语境下既被读作「原子层」又被读作「三层整体」，有歧义。原子层一律称 **tokens**。

## 禁令

1. **禁止裸用「4 态」二字**——写全称：数据态写「状态覆盖（normal/empty/loading/error）」，样式态写「控件四态」。跨域提及必须带归属前缀（pd-ix 文内提控件四态写「控件四态（pd-vd 域）」）。
2. **IX 不写样式值**——`.ix.md` 里不出现 hex / px / 动画时长等视觉参数（线框图的结构标注除外）。
3. **VD 不就地加行为**——原型需要 IX 未定义的行为时走回流登记，不得只落在原型代码里；VD 也不得给 tokens 改名（下游继承以 tokens 表为准）。
