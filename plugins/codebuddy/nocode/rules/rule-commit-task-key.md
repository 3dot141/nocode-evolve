# commit 任务号必须查证，禁止前缀推测

## 触发

任何流程要生成含飞书任务号标注的文本（commit message、PR 标题/描述、全景计划的任务号字段），
且手头只有纯数字工作项 ID（来自飞书链接、任务上下文或用户口述）时。

## 动作

1. 用 meego 查真实 Key：`meegle workitem get --work-item-id <纯数字ID>`（纯数字可跨空间命中，
   返回的 `owned_project` 是真实归属）；从工作项编号/URL 取带类型前缀的完整 Key（f-/g-/m-…）。
2. 用查到的完整 Key 作标注。meego 不可用（CLI 缺失/未授权）→ 停止并向用户要完整 Key，
   不得回退到前缀推测。

## 为什么

飞书侧按完整 Key 关联工作项；前缀写错 = 关联到不存在/错误的工作项。实证（2026-09-07）：
产研任务 7073131785 按仓库 commit 前缀惯例被推测为 `f-7073131785`，实际是
`g-7073131785`——同一仓库三种前缀并存，历史分布不构成任何单件的推断依据。
