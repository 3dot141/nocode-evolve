# 数据库表关系 — 默认使用逻辑关联

设计或修改数据库表结构时，表间关系默认由关联字段和应用层逻辑维护，不创建数据库物理外键约束。

## 触发

- 新建或修改数据库表、DDL、migration
- 设计 ORM model、entity、relation mapping
- 新增或调整一对一、一对多、多对多等表间关系

## 规则

1. 关系字段照常保留，例如 `user_id`、`order_id`，但不声明 `FOREIGN KEY` / `REFERENCES` 约束。
2. 引用完整性、级联更新和删除策略由应用层逻辑维护。
3. 查询与 JOIN 所需的索引、唯一约束等按业务和性能需要独立设计，不因不建外键而省略。
4. 仅当用户明确要求使用物理外键时，才为本次设计或改动创建外键约束。

## 不触发

- 只读查询数据或查看现有 schema
- 不涉及表间关系的单表字段调整
- 用户已明确要求创建物理外键

## 不要

- 不要因为 ORM 支持 relation 就自动生成数据库外键
- 不要把“不创建物理外键”误解为“不需要关系字段或索引”
- 不要在没有用户明确要求时补建外键、级联删除或级联更新约束
