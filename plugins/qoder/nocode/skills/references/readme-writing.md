# README writing — 子目录 README.md 书写方案

共享 reference，被 `{QODER_PLUGIN_ROOT}/skills/references` 引用。子目录 README.md 的结构与形式单源；消费方（projecthub write / dream、dev-land 文档同步）各自按此方案填充，确认机制由消费方自带（write 两拍制 / dev-land 全景单次确认）。

## 总分结构

README.md 总分——「全景 → 功能 → 功能点」层级：

````markdown
# <dir-name>

## 全景

<2-3 句：是什么 / 为谁服务 / 与哪些上下游有边界>

<全景图（形式见下）>

<浅层带注释文件树：顶层模块/文件 + 一句话职责>

## <功能 / 模块 1>

<职责一句话；该功能节是顶层图对应层的展开（见「逐节下钻」）>

### <功能点 1.1>    （仅当确有可展开的点：入口 / 用法 / 关键行为；没有可展开内容就删掉这一层）

## <功能 / 模块 2>
...

## 使用与扩展

<怎么跑 / 怎么扩展 / 注意事项>
````

## 全景图形式（按目录形态选一）

| 目录形态 | 全景图形式 |
|---|---|
| 有明确数据流 / 流水线 / 状态机（入口→处理→裁决→落库这类多级流转） | **分层流水线图**（首选） |
| 纯工具集 / 配置目录 / 静态结构 | 边界图 + 文件树 |

分层流水线图要素（图式模板见 `{QODER_PLUGIN_ROOT}/skills/references/visual-forms.md`「Layered pipeline diagram」）：

- (a) 纵向多框堆叠，框间 `│ ▼` 表达流向——一框 = 一层（阶段 / 产线 / 裁决 / 落库…）
- (b) 框头 = 编号 + 层名 + 括号内机制一句话
- (c) 框内树形条目（`├─` `└─`）+ 每条短注
- (d) **不变式行**——该层必须恒真的等式 / 约束标注在框底（这套图式的灵魂，有就必标）

可选增强（有素材才加，不硬凑）：

- 贯穿关注点（观测 / 错误处理这类跨所有层的维度）用 `┄┄` 分隔线单独成段
- 末尾「关键设计一句话」表：设计名 → 一句话概括

## 逐节下钻

顶层大图是地图，功能节是逐层放大：

- 每个功能节对应顶层图的一层 / 一支，写作时对照图展开——图上的层在正文有节，正文的节在图上有层
- 功能节**自身有内部流程 / 结构**时，节首放该功能的缩微全景图（同样式、范围缩小到本功能）；纯清单型功能节不配图
- 深度按目录复杂度收缩——简单目录 = `全景` + `使用与扩展` 两节，不为凑层级硬拆

## 完整性纪律

- **功能清单先枚举再写作**——从入口 / 导出 / 子目录归纳该目录对外提供的全部功能模块，写作逐项对照；「描述完整」靠枚举不靠自觉
- 每级有形式支撑——全景节必有图或树；功能节按内容选形；连续散文超过一个要点先转形式
- 图优先 ASCII；mermaid 仅在 ASCII 确实画不清时可用于 README.md

## 反模式

- 不堆图——一要点一视图；全景节没有图或树不合格，视图堆满同样不合格
- 不画假流水线——没有数据流的目录硬套多框堆叠，图就成了装饰；该用边界图就用边界图
- 不强行拆层级——简单目录硬拆「功能 1 / 功能 2」是仪式复杂度
- 缩微图不是标配——纯清单型功能节配图是凑形式
