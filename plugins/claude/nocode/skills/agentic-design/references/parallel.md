# parallel — 子 agent 分工

页面文档超过 3 份时并行；3 份以内主 agent 自己做（一致性更好，也省一次交接损耗）。

## 分组

按**模块相关度**分，不按份数均分。同一模块的多屏放一组（共用组件与文案，分给不同 agent 会各自发明细节）。

- 每组 2–4 份
- 组与组之间不共享页面（避免同时改同一个文件）
- 记录型模块（设置、账号、知识库）可以一组，因为它们共用返回栏与分组容器

## prompt 模板

每个子 agent 的 prompt 必须自足，包含下面六块，缺一块就会跑偏：

```text
工作目录 <绝对路径>，文档目录 <design-demos 绝对路径>。

任务：<产出/重绘哪一份，逐条列出文件名>

必读（按顺序）：
1. <design-demos>/_shared-design.md        —— token、骨架、组件类、输出路径
2. <design-demos>/<样板文档>.html          —— 结构模板，照抄它的外壳与类名
3. <源码文件路径>                          —— 真实功能与文案以源码为准

任务内容：
- <每个屏/每个状态要画什么，逐条列>

要求：
- 四段式结构：UI（高保真）· UX（说明+表+原型）· Widget（引用）· Token（引用）
- 复用样板里已有的类；确实需要新增时前缀 <ux> 并在回报里说明
- 真实尺寸：390×844，字号保持 iOS 真值，不用 aspect-ratio 撑高
- 文案以源码为准，不编造功能与数据

不要做的：
- 不改其它三段已有内容
- 不发明新的视觉语言（颜色、字号、圆角只用 _shared-design.md 里的值）

完成后各渲染一次自查（只确认无溢出/裁切，不把截图发回来）：
node <shot-one.cjs> <name> 1340 1200

回报：每份几屏/几组、新增了哪些类及原因、改动文件路径。不要粘贴 HTML。
```

## 为什么每条都不能省

| 模板项 | 省掉的后果 |
|---|---|
| `_shared-design.md` | 每个 agent 自己定颜色和字号，16 份文档长成 16 个产品 |
| 样板文档 | 四段式结构各不相同，合并时无法统一 |
| 源码路径 | agent 编造不存在的功能（今天出现过：给分享扩展画了快记入口） |
| "复用已有类" | 每个 agent 发明一套自己的类名，CSS 膨胀且互相冲突 |
| "不把截图发回来" | 回报被图片撑爆，主 agent 上下文被吃掉 |
| 回报要求"新增类及原因" | 无法判断样式是否跑偏 |

## 完成后的合并检查

子 agent 全部返回后，主 agent 依次做：

1. **结构检测**（见 `verification.md`）：全量跑一遍，不抽样
2. **类名审计**：`grep -o 'class="[^"]*"'` 汇总，看有没有同一语义出现多种类名
3. **抽样目视**：每份看第一屏与最后一屏
4. **一致性检查**：同一元素（如顶栏、返回栏）在不同文档里是否同一套尺寸
5. **重渲染**：改过任何 CSS 后，批量重渲染全部 PNG

## 常见失败模式

| 现象 | 原因 | 处置 |
|---|---|---|
| 子 agent 回报"无溢出"，实际有 | 自报不可信 | 主 agent 跑检测脚本 |
| 各文档的顶栏高度不一致 | 没强制复用样板类 | 统一替换为样板类 |
| 出现源码里没有的功能 | 没读源码或读了但没核对 | 对照源码删除，并在回报里要求补出处 |
| 同一交互在不同页面行为描述矛盾 | 分组时把相关页面拆开了 | 合并到同一 agent 或事后统一口径 |
| 新增大量无人使用的类 | 没有"逐一说明新增类"的要求 | 清理死代码 |
