# Agentic Design

把界面设计从「散落的设计稿」变成「可交付的设计系统文档」。

本 skill 不自己产出视觉方向——方向由用户在 S0 选定的设计 skill 产出；本 skill 负责流程、系统化与验收。

## 何时用 / 何时不用

**用**：需要一整套产品界面的设计文档；已有设计稿要整理成规范；设计与实现脱节需要对齐清单。

**不用**：只做单页视觉（直接用设计 skill）；只改一处样式；纯代码重构；产品需求分析（走 pd-* 系列）。

## 入口判定

| 前提 | 路径 |
|---|---|
| 有代码库 / 已上线界面 | 读代码与现有截图，从现状出发 |
| 无代码 | 采集 brief：目标用户、核心场景、参考产品、约束 |
| 两者都有 | 代码为准，brief 补充意图 |

## 五个阶段

```
S0 工具选择 → S1 现状 → S2 方向 → S3 系统 → S4 页面 → S5 验收
```

每一阶段结束都有用户 gate，未通过不进下一阶段。

### S0 · 工具选择

进入方向前，先问用户用哪个设计 skill 产出方向。列出当前可用的设计类 skill 与「手工」选项，由用户决定。不要替用户选，也不要跳过这一步直接开始画。

产出：`tool-choice.md`（选了谁、为什么、备用方案）。

### S1 · 现状

有代码：读路由/页面结构、组件目录、样式入口、现有截图；无代码：整理 brief。

产出：`问题清单`——每条包含「位置 + 现象 + 证据（截图或代码行）+ 影响」。没有证据的条目不算。

### S2 · 方向

**强制三方向**，用 S0 选定的工具产出三个真实初稿，摆出来等用户选。不允许跳过、不允许只给一个方案、不允许用文字描述代替真实初稿。

产出：三份初稿 + `direction-approved.md`（用户原话、选定方向、不可动约束）。

### S3 · 系统

在选定方向上定义三件事，缺一不可：

1. **Design Token**——色彩、字阶、形状、间距、动效，每项有值、有用途、有使用规则
2. **Design Widget**——组件库，每件一个独立文件，外加一个 index 聚合；按通用组件库分类（导航 / 数据展示 / 数据录入 / 反馈 / 按钮与容器）
3. **交互地图**——页面之间怎么走：聚合视图（全部跨页动作）+ 每页一张卡片（页面间 / 页面内分列）

产出：`ui-overview`、`ux-overview`、`design-widget/`。

### S4 · 页面

每页四段式，顺序固定：

| 段 | 内容 |
|---|---|
| UI | 高保真原型：真实设备尺寸、状态栏、灵动岛、Home Indicator、iOS 真实字号；每屏一句规格 |
| UX | 先说明再展示：交互表（交互 / 说明 / 规格）+ 2–3 组前后对照原型 |
| Design Widget | 本页用了哪几个组件、各自职责；只引用不重复定义 |
| Design Token | 本页实际用到的值；没列出的不许用 |

**并行规则**：页面数 > 3 时派子 agent 分组产出，≤ 3 时主 agent 自己做。
所有子 agent 必须共享同一份 `_shared-design.md`（token、骨架、组件类、输出路径、内容纪律）。
先做 1 份样板，用户确认结构与形态后，才批量铺其余。

### S5 · 验收

全部页面生成完成后，**主 agent 亲自截图审核**（不是让子 agent 自报通过）：

- 结构检测：标签是否被父容器裁切、元素是否越界、网格轨道是否塌陷
- 逐份抽查：至少看第一屏与最后一屏，确认无遮挡
- 对齐清单：设计与现有实现的差异，逐条列出

通过线由主 agent 判断——检测脚本是手段，不是通过标准。

## 硬规则

1. **样板先行**：任何批量产出前先做 1 份，用户确认后再铺开。批量出错 16 份的返工成本远高于一次样板。
2. **子 agent 共享规范**：每个子 agent 的 prompt 必须包含 `_shared-design.md` 路径、输出文件路径、截图命令、需要读的源码文件。
3. **组件只定义一次**：Design Widget 是唯一来源，页面文档只写引用。
4. **截图是自查工具**：不把截图当作交付物逐张汇报；PNG 用于自己验证与最终交付。
5. **用户反馈定位到最小单元**：一次反馈只改对应的屏/组件/文档，不整份重做。
6. **diff 与实测优于描述**：不要声称"无遮挡"而没有跑检测；不要声称"已同步"而没有 grep 验证。

## 产出物结构

```
design-demos/
├── index.html              总入口
├── ui-overview.html        Token + 组件索引 + 使用规则
├── ux-overview.html        交互地图
├── design-widget/          index + w01…wNN 每组件一件
├── spec-mXX-<name>.html    每页四段式
└── _shared-design.md       子 agent 共享规范
```

## 反合理化

| 想法 | 现实 |
|---|---|
| "方向直接按用户说的做" | 强制三方向是规则，跳过等于没做 S2 |
| "先批量写完再统一检查" | 样板没定死就批量 = 集体返工 |
| "子 agent 说通过了就行" | 主 agent 必须自己截图，自报不算 |
| "组件在页面里再写一遍方便阅读" | 两处定义必然分叉，只允许引用 |
| "截图看着没问题" | 眼睛漏掉裁切的概率高于检测脚本 |
