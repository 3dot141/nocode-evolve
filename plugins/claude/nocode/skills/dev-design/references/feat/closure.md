# Feat closure

Check the design in both directions.

## Outcome to evidence

- [ ] The real outcome maps to actors and complete user flows.
- [ ] Every user-flow branch has rules, state, system support, failure behavior, and acceptance evidence.
- [ ] Every applicable competitor insight has provenance and a named impact on scope, flow, rule, or option.
- [ ] Every domain / data-owner crossing has direction, contract, owner, consistency, authorization, retry / compensation, observation, and verification.
- [ ] Every triggered quality or sensitive risk has an enforceable design and proof objective.
- [ ] Release, migration, compatibility, rollback, and cleanup are closed when applicable.

## Solution back to source

- [ ] Every component, contract, store, event, rule, and migration step has a source flow, constraint, risk, or preserve obligation.
- [ ] No solution element exists only because it is fashionable or aesthetically preferred.
- [ ] Every independent obligation can receive one DES ID and one downstream proof result.

## Type Gate

- [ ] No branch is actually an unseparated bug or independent refactor outcome.
- [ ] Independent acceptable outcomes have their own task Logs.

Any failure reopens the responsible F node. Do not compensate by adding prose during writing.
