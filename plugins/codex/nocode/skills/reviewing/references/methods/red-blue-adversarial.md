# 方法卡：red-blue-adversarial（红蓝对抗）

> reviewing 框架方法库 · 评审方法之一。**适合**：方案 / 决策 / 架构选型 / 多方案僵持 / 重构方向——「该不该 / 选哪个 / 行不行」类评判。**不适合**：逐项缺陷核查（用 checklist）、固定维度遍历、工件缺陷发现的双路中立评审（用 `dual-review`——红蓝是**有防守方**的对抗，dual-review 无防守方、两路中立挑错后合并，分界表见该卡）。
>
> 本卡是红蓝对抗能力的**单源**。`skills/red-blue-deep/SKILL.md` 是委派本卡的薄壳（保留独立 skill 入口供用户直触）。

red-blue-adversarial 不是「列 pros/cons」，而是**让红军真攻击蓝军的方案**。核心三件：① 先拆第一性原理，别在错命题上辩论；② 独立性按档位配置——**默认自查不派发**（自攻自确实手下留情，但派发有分钟级成本，升不升由用户拍板）；③ CLAIM 剥离，不把倾向喂给独立路。

## 一、档位判定（必先做这一步，默认最低档）

三档。**默认自查档起步，不派 subagent、不调 codex**；升档只在用户显式要求，或敏感面建议后用户点头（对齐 devflow「默认自审、显式要求才升审」策略；调用方声明强制档位则按声明）。

| 档位 | 触发 | 执行形态 |
|---|---|---|
| **自查档（默认）** | 一切评估/拍板类问题的起始档 | 主会话全程：sequential-thinking 第一性原理拆解 → 蓝军自陈 → 红军自攻 → 结论。琐碎问题（命名/文案/单点小改）拆解与攻防各一两句即可，不硬撑篇幅 |
| **中档** | 用户显式要求（「深度评估 / 独立审 / 找 codex 看看」），或敏感面建议后用户点头 | 主会话做第一性原理（ST）+ 蓝军防守；**红军单路交 Codex**（CLAIM 剥离）；主会话合并两路 → 结论 |
| **重档** | 用户显式要求全面对抗（「红蓝军双路 / 非常仔细 / 全面对抗」），或多方案僵持要拍板、中档后仍不收敛，经用户点头再升 | **两路独立完整对抗**：隔离 subagent 一路 + Codex 一路，各自拿同一份 CLAIM 剥离任务包，独立走「第一性原理拆解 → 内部蓝军防守 → 内部红军攻击 → 结论」；主会话不预拆命题（防锚定），只打包 + 合并裁决 |

**敏感面提醒**（不自动升档）：命中不可逆 / 跨模块 / 架构·选型 / 资金 / 数据迁移 / 多方案僵持 → 向用户**一句话建议**中档或重档，用户点头才派；agent 不得自行升档，模糊信号（「快速看看」）不算授权。

**边界示例**：「变量名 `user_id` 怎么样」→ 自查档一两句了结（「比 `uid` 好——后者太泛，全局搜会撞一堆无关引用」）；升主依赖大版本 + 用户说「仔细评估下」→ 建议中档；「PostgreSQL vs MongoDB 当主存储」双方各有强支撑要拍板 → 建议重档。

## 二、各档流程

### 自查档（默认）— 主会话四步，零派发

**前置：sequential-thinking 开启**（`mcp__sequential-thinking__sequentialthinking`，多分支推演 / 中途回退重拆不丢主线；不可用 → 明说「无结构化思考辅助下进行」后继续，降级不阻断）。

1. **第一性原理拆解**：剥到最基础的假设——这个决定要满足的**根本需求**是什么？哪些是真约束，哪些是历史包袱 / 沿用习惯？把伪需求剔掉。拆完才进蓝/红，否则在错误命题上辩论。
   > 例（会话要不要上 Redis）：根本需求 = 跨进程共享会话 + 进程崩溃不丢登录态；真约束 = (a) 多进程共享 (b) 不丢登录态；历史包袱 = 「大家都用 Redis」是惯例不是约束；伪需求剔掉 = 高性能（QPS 实际很低）、持久化（重登即可）。→ 真问题是「跨进程共享 + 短期可靠 KV」，候选 = Redis / sticky+内存 / Memcached / 数据库表，Redis 只是其一。
2. **蓝军自陈**：列提议方案的优势 / 适用场景 / 隐含好处。必须落到具体场景（「X 时候有用」），不能空对空（「灵活性更好」）。
3. **红军自攻**：换立场真攻击——弱点和隐藏代价（落到「实现时遇到 X」「N 月后出现 Y」，不要「理论上可能」）、盲区、替代方案。自查纪律：放下已有倾向认真找茬，不是给既定结论找台阶。
4. **结论**：「**倾向 A —— 因为 [关键蓝军论点]；但承认 [红军关键发现] 是真问题，[如何缓解]**」。成立的红军发现必须在结论体现。**不要「看情况 / 都有道理 / 你怎么想」——这是逃避。**

自攻自手下留情是结构性风险——自查档红军力度天然弱于隔离红军，结论如实标注「独立性：无（自查）」；用户对结论有疑 → 建议升中档。

### 中档 — 蓝军在主会话，红军单路交 Codex

自查档四步照走，差别在第 3 步：**红军不自演，单路交 Codex**（经 `rule-codex-review` 场景 1 通道派发）。

- **CLAIM 剥离**：只传方案 + 约束 + Step 1 拆出的真约束，**不传蓝军分析和你的倾向**（传了 reviewer 会锚定失去独立性）。事实随 **Context Capsule** 补齐（skeleton §4.1：已拍板决策 / 被否决方案及原因 / 非目标 / 预算 + 已知缺失上下文声明）——剥结论、留事实。
- **红军输出四维**：优势（蓝军遗漏的好处）/ 弱点和隐藏代价 / 盲区 / 替代方案。
- **合并两路**：红军提出、蓝军未覆盖的点 = 盲区，逐条判成立性；成立的纳入结论。**蓝军不外派**——防守论证需要完整会话上下文（拍板 / 约束 / 历史都在会话里）。
- **降级**：Codex 报错 → fallback 改派 subagent 单跑红军（skeleton §4.2），独立性标「同源（降级）」并明说。

### 重档 — 双路独立完整对抗

主会话**不做第一性原理拆解、不当蓝军**——预拆命题 = 把自己的理解锚给两路，两路变确认路。主会话只做三件事：

1. **打包**：同一份任务包 ×2——被评估方案原文 + 约束 + Context Capsule（CLAIM 剥离，skeleton §4.1），任务指令写明四步：「先第一性原理拆解（根本需求 / 真约束 / 伪需求）→ 内部蓝军防守 → 内部红军攻击 → 给出倾向 + 缓解的结论」
2. **双路派发**：隔离 subagent（general-purpose）一路 + Codex（经 `rule-codex-review` 场景 1，prompt 换成上述完整对抗任务包）一路，同时独立跑
3. **合并 + 判决**（回主会话）：两路的结论与关键论点比对——交集 = 高置信直接采纳；分歧点逐条裁决（此时主会话才引入会话上下文当裁判依据）；最终结论格式同自查档第 4 步，标注「独立性：双路独立（同源 + 异源）」

**降级**：Codex 报错 → 只剩 subagent 单路完整对抗，独立性标「同源单路（降级）」并明说，不静默当双路。

### Doubt Theater 检测（各档通用）

红军/独立路返回的弱点盲区全是「理论上可能」无具体场景 = 走过场。两个选择：换审查角度重跑（技术↔运维 / 性能↔安全 / 短期↔长期）；或承认无有效反驳，结论直接采纳蓝军。不要为「也得说点什么」把站不住的发现当真。

### 三轮收敛上限

sequential-thinking 允许回退重拆，最多 3 轮。第 3 轮仍不收敛 = 缺用户输入，停下问用户补约束（「你更在意 X 还是 Y？」），不要空转。

## 三、输出契约

产出 `findings[] + verdict`，映射 `references/findings-contract.md`：

- **自查档**：结论段落（倾向 + 理由 + 真问题 + 缓解）即可；琐碎问题一句表态。调用方要求结构化 → 记 `kind=normal` 的 suggestion 承载理由。
- **中档 / 重档**：成立的每条发现 → 一条 finding。
  - `axis` = `优势` / `弱点` / `盲区` / `替代方案`
  - `severity` = 按影响：阻塞性硬伤 critical / 应缓解的真代价 warning / 可选优化 suggestion
  - `source` = `蓝军` / `红军(Codex)` / `红军(subagent，codex fallback)` / `对抗路(subagent)` / `对抗路(Codex)`
  - 弱点类 finding 若是代码/事实声明，受 Evidence Gate 约束（缺 location 的 critical 降级 `kind=open-question`）
- **verdict**：`{ approved, counts, recommendation }`，其中 `recommendation` = 结论原文（倾向 + 关键理由 + 真问题 + 缓解）+ 独立性标注（`无(自查)` / `异源红军单路` / `双路独立` / 降级说明）。**verdict 是 red-blue 的主产物**——findings 是支撑，结论的「倾向 + 缓解」不能被 C/W/S 列表压扁。

## 四、派发要点（其余见 skeleton）

- **自查档**：零派发，主会话 ST 四步。
- **中档**：红军单路 Codex；蓝军不外派（防守需要完整会话上下文）。
- **重档**：subagent + Codex 双路各自完整对抗；主会话不预拆、不预辩，只打包 + 合并裁决。
- 派发通道 / codex 报错 fallback / 降级链见 skeleton §4.2 与 `rule-codex-review`，本卡不复述。sequential-thinking 不可用 → 明说后仍进第 1 步。

**反例**：默认就拉 codex（升档权在用户，agent 不得自行升）/ 自查档红军敷衍走过场（自攻要真攻，站不住的结论标独立性让用户判断）/ 重档主会话先拆好第一性原理再喂两路（锚定，两路变确认路）/ 独立路传了倾向（reviewer 被锚定）/ 发现了盲区结论没体现（做了等于没做）/ 架构级僵持停在自查档也不向用户建议升档（该建议不建议 = 失职）。
