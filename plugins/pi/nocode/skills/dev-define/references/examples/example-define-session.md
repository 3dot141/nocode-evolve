# Example: 从模糊需求到确认 restate

演示一次完整的 Define 会话——用户抛出"给后台管理系统加导出功能"，如何收敛成一份用户确认的 restate。

## 用户输入

> "给后台管理系统加个导出功能。"

## Step 1: 场景分类

跨文件 + 实现路径不明（导出什么、什么格式、谁用都没说）→ workflow.decision.request 确认为 **Standard**（暂无明显架构/选型决策；若后续发现需异步导出架构再升 Full）。

## Step 2: 探索现状（代码）

- `[Read admin/orders/list.tsx:40]` 列表已有筛选器（日期范围、状态）
- `[Read api/orders/query.ts:88]` 后端 query 支持分页，单页上限 100
- `[推断]` 现无任何导出端点

## Step 3: 假设先行

> **Hypothesis**：导出的是"订单列表当前筛选结果"，CSV 格式，运营人员用来做对账。
> **CONFIDENCE: 60%** — 格式和数据范围是猜的，需确认。

## Step 4: 澄清循环（代码不能自答的才问）

1. **导出哪些数据？** → workflow.decision.request：[当前筛选结果 / 全表 / 选中行] → 用户选"当前筛选结果"
2. **什么格式？** → [CSV / Excel / both] → 用户选 CSV
3. **数据量级？**（影响同步还是异步）→ 用户："单次最多几千行" → 同步即可，不需异步架构 → 确认 Standard

**95% 测试**：能预测用户对接下来三个问题（编码格式、文件名规则、权限）的回答吗？能（UTF-8 BOM、含时间戳、复用列表页权限）→ 退出循环。

## Step 5: 产出 restate

> **目标**：运营在订单列表页点"导出"，把当前筛选结果导出为 CSV 文件。
>
> **Quality Bar**：
> - 导出内容 = 当前筛选条件命中的全部订单（跨页，不止当前页）
> - CSV 含 UTF-8 BOM（Excel 打开不乱码）
> - 文件名含导出时间戳 `orders-20260624-1530.csv`
> - 复用列表页的数据权限（看得到才导得出）
>
> **Out of Scope**：
> - Excel/PDF 格式（本次只 CSV）
> - 异步/后台导出（数据量小，同步够用）
> - 自定义导出字段（用列表页固定列）

## Step 6: 用户确认

workflow.decision.request 三选 → 用户选"确认"。Define 完成，进 Plan。

---

**这个示例的关键点**：hypothesis 先给 + 标置信度；代码能自答的（权限、分页能力）不问用户；Out of Scope 把"看似相关但本次不做"的显式排除，防止范围蔓延。
