# Step 3 展开：逐交互拆解

## 3a. 提取交互清单

从 PRD 使用路径提取每个需要设计的**交互点**。路径是"用户要完成什么"，交互是"用户在每一步具体做什么操作"。

### 示例

PRD 路径 `订单.P1`（用户下单）拆出交互：

- 订单.P1.1: 浏览商品列表
- 订单.P1.2: 查看商品详情
- 订单.P1.3: 加入购物车
- 订单.P1.4: 编辑购物车（改数量/删除）
- 订单.P1.5: 确认订单（地址/备注）
- 订单.P1.6: 选择支付方式并提交

### 跨域路径

跨域路径（`跨域.N`）展开成端到端交互链——把串联的几条领域路径的交互连成一条用户实际走完的流程。

### 系统路径

系统路径（`系统.N`）无界面不进交互清单，但要识别"触发后用户看到什么"（如支付回调后支付等待页切成成功态），纳入相关交互的状态。

## 3b. 逐交互四块格式

每个交互写进 `.ui.md` 的格式：

```markdown
### 订单.P1.1: 浏览商品列表

**竞品做法**
- [SOURCE: url] 竞品A: 瀑布流 + 筛选栏左侧固定
- [SOURCE: url] 竞品B: 卡片网格 + 顶部标签筛选

**设计决策**
[我们怎么做 + 为什么（引用竞品 + PRD 约束）]

**线框图**
[ASCII/文字版布局: 区块划分 + 内容清单]

**状态覆盖**
| 状态 | 表现 |
|---|---|
| 正常 | 商品列表正常展示 |
| empty | "暂无商品" + 引导 |
| loading | 骨架屏 |
| error | 加载失败 + 重试 |
```

### 四块要求

| 块 | 硬约束 |
|---|---|
| 竞品做法 | 每条标 `[SOURCE: url]`，不凭印象编 |
| 设计决策 | 必须引用竞品做法或 PRD 约束作为依据，不拍脑袋 |
| 线框图 | ASCII 布局，标出区块和内容，不能只文字描述 |
| 状态覆盖 | 正常 / empty / loading / error 四态缺一不可 |

## 3c. 逐交互校验

每个交互展示给用户校验：

- "竞品做法对吗？漏了什么？" → 补调研
- "设计方向不对，改成 X" → 调整设计
- "够了 / 没问题" → 该交互锁定，进下一个
- 同一交互最多 3 轮

**全部交互锁定后才进 3d。**

## 3d. IA 汇总

从**锁定的交互**汇总出（不是凭空画）：

- 页面/视图清单 + 层级关系
- 导航结构
- 每个页面包含哪些交互
- 页面间的跳转关系

展示给用户批准："交互拆解和 IA 是这样，确认了我再往视觉/原型走。"
