# Step 4 展开：视觉方向 + 保真度 + 渐进式升级

> pd-ui Step 4 的展开。主线只放决策骨架，这里放三轴定义、发散方法、升级规则、保真度细则。

## 1. 视觉三轴

视觉方向不靠"感觉好看"，靠三个可定位的轴。每个方向就是三轴上的一个坐标。

### 轴 A：布局密度

```
紧凑信息密集 ←──────────────→ 宽松留白
```

- **紧凑端**：单屏塞更多信息，行高小、间距窄、模块挨得紧。适合专业用户高频操作、数据密集场景。参考：Linear（issue 列表）、Bloomberg 终端。
- **宽松端**：留白多、单屏信息少、每个元素呼吸感强。适合内容消费、降低认知负担。参考：Notion（文档页）、Apple 产品页。

### 轴 B：视觉强度

```
克制中性 ←──────────────→ 表现力强
```

- **克制端**：低饱和、少颜色、几乎无装饰，让内容本身说话。参考：Stripe Dashboard、Vercel。
- **表现力端**：大色块、渐变、插画、动效，视觉本身是卖点。参考：Linear 落地页、Framer 模板。

### 轴 C：调性

```
专业严肃 ←──────────────→ 友好轻松
```

- **专业端**：等宽字体、精确数值、克制文案，传达"可靠、严谨"。参考：GitHub、AWS Console。
- **友好端**：圆角、暖色、口语文案、emoji/插画，传达"亲切、好上手"。参考：Duolingo、Slack。

## 2. 方向发散

### 原则

- 给 **2-3 个明显不同的方向**——不是一个方向的微调（"蓝一点 vs 更蓝"不算两个方向）
- 三轴位置要拉开：A 方向偏紧凑专业，B 方向就该偏宽松友好，让用户看到真实的取舍
- 用户可以**混搭**："要 A 的紧凑布局，但用 B 的友好调性"——记下混搭组合作为最终方向

### 每个方向的描述格式

```
方向 X「<一句话标签>」
- 一句话描述：<这个方向给人的整体感觉>
- 三轴位置：布局<紧凑/中/宽松> · 强度<克制/中/表现力> · 调性<专业/中/友好>
- 参考产品：<1-2 个类比，让用户有具体画面>
- 适用：<什么场景下这个方向最对>
```

### 示例：一个"开发者资源管理工具"的 3 个方向

```
方向 A「工具感」
- 描述：像一个高效的命令行工具，信息密集，操作快
- 三轴：布局紧凑 · 强度克制 · 调性专业
- 参考：Linear + Raycast
- 适用：目标用户是工程师，每天高频使用，要的是效率不是惊艳

方向 B「编辑器感」
- 描述：像一个干净的写作工具，留白多，专注内容
- 三轴：布局宽松 · 强度克制 · 调性中性偏友好
- 参考：Notion + Bear
- 适用：用户停留时间长，需要降低视觉疲劳

方向 C「仪表盘感」
- 描述：数据可视化驱动，卡片网格，一眼看全局状态
- 三轴：布局中等 · 强度表现力 · 调性专业
- 参考：Grafana + Vercel Dashboard
- 适用：核心价值是"看状态"，数据展示是第一位
```

呈现给用户时，每个方向配一句"它牺牲了什么"——方向 A 牺牲了视觉惊艳换效率，方向 C 牺牲了信息密度换可读性。让取舍显性化。

## 3. 渐进式升级

每一档是完整交付物，升档在前一档基础上**加东西**，不推翻。升档前先回查 `.ui.md` 已有内容，确认升级基线。

### ASCII → 低保真：加视觉，不改交互结构

交互结构（页面、区块、流程）已在交互阶段锁定，这一步只往上铺视觉皮：

| 加什么 | 具体 |
|---|---|
| 配色方案 | 给出实际 hex：背景 `#09090b`、主色 `#3b82f6`、文字 `#fafafa` |
| 字号字重 | 标题 22px/600，正文 13px/400，标签 10px/500 |
| 间距值 | 卡片内边距 18px，模块间距 28px，元素间距 8px |
| 圆角 | 卡片 14px，按钮 999px（pill），输入框 8px |
| 阴影 | 卡片 hover 时 `0 0 24px rgba(59,130,246,0.1)` |

**不允许**：借升级之名改 IA、改页面结构、改交互流程——那是回到交互阶段，不是升保真度。

### 低保真 → 高保真：加交互，不重画页面

页面静态视觉已在低保真锁定，这一步让它"动起来、点得动"：

| 加什么 | 具体 |
|---|---|
| 导航逻辑 | 点侧边栏跳页、点行展开抽屉、面包屑回退 |
| 4 态 | hover / active / focus-visible / disabled，每个交互元素都要有 |
| 边界态 | empty（无数据引导）/ loading（骨架屏或 spinner）/ error（错误提示 + 重试） |
| 过渡动效 | 抽屉滑入 `transition: transform 0.2s`、页面切换淡入 |

**不允许**：借升级之名重新设计页面布局、换配色、改视觉方向——视觉已在低保真定稿，高保真只加行为层。

### 升级红线

- 升档时推翻前一档的设计决策 = 违反渐进式披露。如果真要改前一档，回到对应阶段重走，并告知用户"这不是升级，是返工"。
- 跳档（ASCII 直接到高保真）= 在未经视觉确认的骨架上做交互，返工率高。除非用户明确要求，否则逐档走。

## 4. 保真度细则

| 档 | 产出物 | 落到哪 | 判定标准 |
|---|---|---|---|
| **ASCII** | ASCII 线框 + 视觉方向文字描述 | 直接写入 `.ui.md` | 结构和流程能拍板，不需要看真实视觉 |
| **低保真** | 静态 UI（截图 / 静态页面） | Claude Design 项目 或 `.ui-prototype.html` | 给**具体值**：写 `#3b82f6` 不写"某种蓝"，写 `18px` 不写"适中间距" |
| **高保真** | 可交互原型 | 同上 | 关键流程**走得通**：能点、能跳、能看到 4 态和边界态 |

### 低保真的"具体值"要求

低保真最容易翻车的点是给模糊描述。检查清单：

- ❌ "主色用蓝色" → ✅ "主色 `#3b82f6`"
- ❌ "字号适中" → ✅ "正文 13px，标题 22px"
- ❌ "圆角卡片" → ✅ "卡片圆角 14px"
- ❌ "有点间距" → ✅ "模块间距 28px"

低保真给不出具体值 = 没真正做低保真，只是把 ASCII 换了个说法。

### 高保真的"走得通"要求

高保真不是更漂亮的低保真，是**能演示完整流程**。验收：随便挑一条 PRD 使用路径，从入口点到终点，每一步都能点、都有反馈、边界态都覆盖。中间断一处 = 高保真不完整。
