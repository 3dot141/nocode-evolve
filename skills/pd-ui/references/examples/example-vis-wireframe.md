# 示例：低保真 wireframe（团队协作邀请流程）

> 这是一份**填好的**低保真设计样例，给 pd-ui 出 wireframe 时对照颗粒度用。不是模板——模板见 SKILL.md Step 7。
> 场景：Ledgerly 账本所有者邀请成员加入（对应 PRD 的 US-1/US-2/US-3）。Fidelity = 低保真。

---

## Information Architecture

```
账本设置 (Settings)
├── 基本信息
├── 成员管理 (Members)          ← 本次新增
│   ├── 成员列表
│   ├── 邀请成员 (弹窗)
│   └── 成员权限编辑 (行内)
└── 危险操作
```

导航：成员管理是「账本设置」下的二级 tab，不进主导航（低频操作）。

## Key Flows

**Flow 1: 所有者邀请成员**（对应 US-1）
entry: 成员管理页点「邀请」→ 输入邮箱 + 选权限 → 发送 → 看到"邀请已发送"待接受状态 → done

**Flow 2: 成员接受邀请**（对应 US-2）
entry: 邮件点链接 → 落地页显示"X 邀请你加入账本 Y" → 已登录直接接受 / 未登录先登录再接受 → 进入账本 → done

**Flow 3: 调整成员权限**（对应 US-3）
entry: 成员列表点某成员的权限下拉 → 选 viewer/editor → 即时保存 → done

## Wireframe — 成员管理页

```
┌─────────────────────────────────────────┐
│ 账本设置 > 成员管理          [+ 邀请成员] │
├─────────────────────────────────────────┤
│ 头像  Alice (你)        所有者   —        │
│ 头像  Bob               [可编辑▾]  移除   │
│ 头像  carol@x.com  待接受  [只读▾]  撤销  │
└─────────────────────────────────────────┘

状态列表：
- 正常：成员列表 ≥1 行（至少有所有者自己）
- empty：理论不存在（所有者恒在）—— 故无 empty 态
- loading：列表骨架屏 3 行占位
- error：加载失败 → "成员加载失败，重试" + 重试按钮
```

## Wireframe — 邀请弹窗

```
┌───────────────────────────┐
│ 邀请成员              [✕]  │
│ 邮箱: [________________]   │
│ 权限: ( ) 只读  (•) 可编辑 │
│            [取消] [发送邀请]│
└───────────────────────────┘

状态：
- 正常：填邮箱→发送
- error：邮箱格式错 → 输入框下红字提示；已是成员 → "该用户已在账本中"
- loading：发送中按钮转圈禁用
```

## Visual Direction（低保真档只描述，不出稿）

- **方向 A — 克制中性**：复用现有设置页样式，成员行用列表密排。适用：和现有 UI 一致，开发快。参考 Linear 设置页。
- **方向 B — 卡片化**：每个成员一张卡，头像大、权限标签醒目。适用：成员少、想强调"人"。参考 Notion 成员页。
- 推荐 A —— 协作是工具性功能，一致性 > 表现力。最终由用户选。
