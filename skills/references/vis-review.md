# vis-review — 交互视觉设计评审

**评审对象**: pd-vis 的 `.ui.md` 产出
**评审模式**: red-blue 双模型交叉审

## 流程

1. **蓝军（Claude）**：按维度表逐项审查 `.ui.md`，列出通过项 + 疑点
2. **红军（Codex）**：把 `.ui.md` 原文 + 维度表交给 Codex 独立攻击。**CLAIM 剥离**——不传蓝军结论
3. **合并 findings**：去重合并，Critical / Warning / Suggestion 分级
4. **Critical 必须修复**再交付

Codex 不可用 → 降级 Claude 自演红军（标注降级）+ red-blue-deep 对抗框架。

## 审查维度

| 维度 | 检查什么 |
|---|---|
| 竞品参考充分度 | 竞品探索做了吗？文字说明/HTML/截图三块有吗？不是凭空画的？ |
| PRD 路径覆盖 | 每条使用路径都有对应的交互流吗？系统路径的用户可见反馈设计了吗？ |
| 状态完整性 | 每个关键页的 empty/loading/error 都设计了吗？不是只画了正常态？ |
| 信息层级 | 每屏最重要的东西最突出？视觉层级清楚？ |
| 一致性 | 同类元素处理一致？导航/按钮/交互模式统一？ |
| 交互流连贯 | 从入口到完成目标的路径顺畅吗？死胡同？回退方式？ |
| 可行性 | 这个设计开发能实现？没有依赖不存在的能力？ |
| 方向发散 | 给了 2-3 个视觉方向吗？不是赌单一方向？ |
| 简化检查 | 有没有过度设计？能不能用更简单的交互达到同样效果？信息密度合适吗？ |

## findings 格式

```
| # | 维度 | 级别 | 发现 | 建议 | 来源 |
|---|---|---|---|---|---|
| 1 | 状态完整性 | Critical | 支付页缺 error 态 | 补支付失败/超时状态 | 红军(Codex) |
| 2 | 简化检查 | Suggestion | 设置页层级过深(3层) | 合并到 2 层 | 蓝军 |
```
