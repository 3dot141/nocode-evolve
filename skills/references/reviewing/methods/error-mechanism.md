# 方法卡：error-mechanism（按错误机制核查，HECR）

> reviewing 框架方法库 · 评审方法之一。**适合**：代码 diff、实现细节——逐项清单容易「看过即过」、需要**主动预判作者最可能在哪类机制上出错**的对象。Heuristic Error-Class Review（HECR）。**不适合**：方案选型判断（用 red-blue-adversarial）、高层设计评审（用 perspective-based）。
>
> ⚠️ 业界证据（设计 §2.3）：按**错误机制**找比按维度清单找更主动——不是「这条维度通过吗」，而是「人在这类场景最容易犯哪种错，这里中招了吗」，把 reviewer 的注意力导向高发错误类。

## 一、维度 / 思路

error-mechanism 不遍历功能维度，而遍历**人类/AI 写代码时反复出现的错误机制**，逐类去 diff 里找对应高发点：

| 错误机制 | 高发场景 | 找什么 |
|---|---|---|
| **边界 / off-by-one** | 循环、切片、分页、区间 | `<` vs `<=`、空集合、首尾元素、`len-1` |
| **空值 / 未初始化** | 可选返回、解构、默认值 | null/undefined/零值未处理、可选链缺失 |
| **错误假设** | 「这个值一定非空 / 已排序 / 唯一」 | 没校验的前置假设、隐式契约 |
| **并发 / 时序** | 共享状态、异步、回调 | 竞态、未加锁、await 顺序、双重提交 |
| **资源泄漏** | 文件 / 连接 / 监听器 | 未关闭、未解绑、异常路径未释放 |
| **错误处理** | try/catch、错误码、降级 | 吞异常、错误路径未测、降级未明说 |
| **类型 / 转换** | 隐式转换、序列化、精度 | 字符串↔数字、浮点精度、时区/编码 |
| **状态机 / 不变量** | 多步流程、缓存一致性 | 中间态非法、缓存与源不一致、回滚不完整 |
| **复制粘贴变体** | 重复结构改了一处漏改另一处 | 多分支只改了 N-1 个、变量名复用残留 |

机制集**按代码性质裁剪**——并发代码重点查竞态/时序，纯计算重点查边界/精度。

**纪律**：① 对每类机制问「这段代码有没有这类场景？有的话中招了吗？」，没有该场景就显式跳过；② 命中落到 `file:line` + **触发输入**（什么输入会让它出错——这是 error-mechanism 的招牌：能给出复现条件）；③ 给不出具体触发条件的「理论上可能」按 Doubt Theater 处理，降为 suggestion 或剔除。

## 二、输出契约

产出 `findings[]`，映射 `{NOCODE_SKILL_REF}/reviewing/findings-contract.md`：

- 每条 finding：`axis` = 机制名（`边界` / `并发` / `空值`……）；`location` = `file:line`（**必填**）；`evidence` = 触发该错误的具体输入/状态（招牌字段）；`severity` = C/W/S；`fix` 给 Structural Remedy（改结构消除整类错误，优先于堵单点）。
- **Evidence Gate 在此尤其严**：error-mechanism 的 critical/warning 必须有 `location` + 可复现的触发条件，否则降 `kind=open-question`——「猜测式指控」在错误机制里最易发生。
- `verdict.counts` 汇总。

## 三、派发策略

| 模式 | 派 subagent | 调 codex | 说明 |
|---|---|---|---|
| **自查**（默认） | 否 | 否 | 主 agent 拿机制表逐类扫 diff（`selfApply`） |
| **异源交叉**（重档 / 关键路径） | 是 | **是** | codex 异源跑一遍机制扫描——不同模型对错误类的敏感点不同，异源交叉补盲区 |

档位：
- 轻档 / 小 diff → 自查
- 重档 / 并发/资源/状态机这类高危机制密集的 diff → 叠加 codex 异源（作为 checklist 的备选方法，见 §4.3 选择表「代码 diff 备选 = error-mechanism」）

异源走框架公共能力：CLAIM 剥离（只传 diff + 机制表，不传已发现项）、codex 不可用 → 单 subagent + 明说降级。
