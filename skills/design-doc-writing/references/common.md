# 通用配件

跨所有 layer × intent 组合都可能用到的章节。**按需添加**，不适用就**不写**——保留空标题或写「N/A」比删掉更糟，它在告诉 reviewer「我没想过这个」。

## 备选方案与取舍

考虑过什么其他方案 → 否决理由。**复杂任务建议写**——没写出来 = 你没想过 = reviewer 会质问「为什么不用 X」让你返工。

- **方案 B（被否决）**：xxx。否决因为 yyy。

> 注：决策类文档（intent=decision）已把「Alternatives Considered」放在主线节，无需重复挑此节。

## 测试策略

单测 / 集成 / 端到端 / 人工验证 各覆盖什么具体场景。

> 提示：feature 主线节里已有「验证」节；如果验证内容简单，不必再开此节。两节并存的场景：「验证」讲怎么判定做对了，「测试策略」讲测试代码怎么组织。

## 监控与可观测

新增指标、日志、告警。生产服务、用户面功能强烈建议写。

## 安全 / 权限

授权检查、敏感数据处理、审计日志。涉及用户数据 / 外部接入 / 跨权限边界时**必写**。

## 性能预算

QPS、延迟、资源消耗预期。高频路径、用户面、批处理任务建议写。

## 迁移与发布

灰度策略、向后兼容性、迁移脚本、回滚预案。

> 注：refactor 主线节里已有「迁移路径」「回滚预案」；refactor 文档不要重复挑此节。

## 时间预算

预计花多少人天，分到各阶段/步骤。重构、大功能可写。
