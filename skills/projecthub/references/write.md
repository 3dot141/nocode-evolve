# /projecthub write：子目录文档写入

为项目子目录写入/更新 AGENTS.md（agent 工作约束）和 README.md（人类可读文档）。

**被 `/distill` 调用**（distill 路由 `docs:subdir` 出口时传入候选）。也可用户直接 `/projecthub write <dir>` 独立写入。

## 入参

### 被 distill 调用时

distill 传入 `arguments.payload.candidates[]` 结构化候选；不得读取扁平顶层字段：
```
{ summary, target_dir, target_file, body }
  target_dir   目标子目录路径 (相对项目根)
  target_file  agents | readme | both
  body         要写入的内容片段
```

### 独立调用时

`/projecthub write <dir-path> [agents|readme|both]`
- `<dir-path>`：目标目录（相对项目根或绝对路径）
- 第二参数：写入哪个文件，默认 `both`

无参数时提示用法。

## 视觉形式（AGENTS.md 与 README.md 共用的表达纪律）

形式词汇已从 `show-me` 内化到下表，按本表执行，不需要也不应再调用 show-me：

| 要表达的内容 | 形式 |
|---|---|
| 目录结构 / 文件布局 | 浅层带注释文件树（≤2 层） |
| 并列分类 / 清单 | 表格 |
| 工作流 / 决策规则 | 编号列表 / 迷你决策树 |
| 机制 / 数据流 / 边界 / 依赖方向 | ASCII 图 |
| 前后对比 | diff 形态块 |

纪律：

- 一要点一视图——不为“显得专业”堆图，一个视图只讲一个点
- 视图紧贴它支撑的文字，不集中堆到文末
- 树/图注释只写真实现状——不写会让引用检查误报的假路径
- 两个文件都不内嵌 HTML；ASCII 优先（不依赖渲染器），mermaid 仅 README.md 可选且仅当 ASCII 画不清

## AGENTS.md 内容规范

子目录 AGENTS.md 是给 agent 看的工作约束。

````markdown
# <dir-name>/ — <一句话定位>

<该目录的核心职责，2-3 句话>

## 约束

1. <在这个目录工作时必须遵守的规则——具体可执行>
2. <禁止做的事情>
3. <特殊工作流要求>

## 结构

<浅层带注释文件树，只列有意义的条目>

```text
src/
├── parser.ts    # 入口：把 X 解析为 Y
└── render/      # 渲染子模块（细节见其 README.md）
```

## 相关

- <与其他目录的依赖关系>
````

**写法原则：**
- 只写 agent 需要知道的约束，不写人类背景知识
- 约束必须具体可执行（“不要手改生成物” 好，“注意代码质量” 差）
- 引用具体文件路径
- 保持简短，单个 AGENTS.md 不超过 80 行

## README.md 内容规范

子目录 README.md 是给人看的文档，总分结构——「全景 → 功能 → 功能点」层级：

````markdown
# <dir-name>

## 全景

<该目录在系统中的角色，2-3 句：是什么 / 为谁服务 / 与哪些上下游有边界>

<ASCII 全景图：目录与系统其它部分的边界、依赖方向，一屏能看完>

<浅层带注释文件树：顶层模块/文件 + 一句话职责>

## <功能 / 模块 1>

<职责一句话；按内容选形式：流程 → ASCII 流程图，并列能力 → 表格>

### <功能点 1.1>    （仅当确有值得展开的点：入口 / 用法 / 关键行为；没有可展开内容就删掉这一层）

## <功能 / 模块 2>
...

## 使用与扩展

<怎么跑 / 怎么扩展 / 注意事项>
````

**总分规则：**
- 功能清单先枚举再写作——从入口 / 导出 / 子目录归纳该目录对外提供的全部功能模块，写作逐项对照；「描述完整」靠枚举不靠自觉
- 深度按目录复杂度收缩——简单目录 = `全景` + `使用与扩展` 两节；功能点层只在确有可展开内容时出现，不为凑层级硬拆
- 每级有形式支撑——全景节必有 ASCII 图或文件树；功能节按内容选形；连续散文超过一个要点先转形式
- 图优先 ASCII；mermaid 仅在 ASCII 确实画不清时用于 README.md

## 执行流程

### Step 1: 分析目录

1. 确认目标目录存在（不存在 → 报错停止）
2. `ls -la` 列出目录内容
3. 读关键文件（package.json / index.* / 入口文件 / 配置文件）
4. 已有 AGENTS.md 或 README.md → Read 全文
5. 理解目录职责、与上下游的关系
6. 归纳功能清单（README 完整性的对照基准）：从入口 / 导出 / 子目录列出全部功能模块，写作时逐项对照

### Step 2: 生成/更新内容

**新建（目标文件不存在）**：
- 基于 Step 1 分析，按上方内容规范生成
- 展示与确认走两拍制（见下）

**更新（目标文件已存在）**：

```
已有内容是否仍准确？
     │
     ├─ 准确 + 有新内容补充 ──→ 融合新内容到合适位置（不末尾 paste）
     │
     ├─ 部分过时 ──→ 更新过时部分 + 融合新内容
     │
     └─ 大部分过时 ──→ 重写（按当前内容规范重排结构）
```

更新路径不做全篇格式升级——以内容准确为先，避免格式重排制造 diff 噪音；仅重写路径按当前内容规范产出。

**展示与确认（两拍制）**：生成的文档全文几乎必然超过 10 行，按结构化决策 payload 自足约定，禁止「文本展示 + 同回合 ask」：

1. 两个目标文件的全文作为回合末文本输出（各自标注目标路径），结束回合，不再接工具调用
2. 用户确认后，下一回合执行写入

仅 ≤10 行的小改（如补一条约束）才可用结构化决策在同回合确认。重写路径的新旧对比用 diff 形态块呈现，超过 10 行时同样走两拍制。

### Step 3: 写入

用户确认后写入文件。

被 distill 调用时，body 已包含内容 → 仍需 Step 1 分析确认 body 与目录实际状态一致，不盲写；**事实不动、形式可转**——body 缺结构（长段落堆砌）时按「视觉形式」转成对应形式，不改变任何事实陈述。

### Step 4: 报告

```
projecthub write 完成：
  + module-a/AGENTS.md (新建, 28 行)
  + module-a/README.md (更新, +12 行)
```

## 反模式

- 不末尾 paste——融合到合适章节
- 不写空泛约束——“保持代码整洁” 等于没写
- 不照搬 .agents-personal 内容——两者受众不同（共享约束 vs 个人知识）
- 不在 AGENTS.md 写人类背景故事——agent 不需要 “本目录创建于 2024 年”
- 不堆图——一要点一视图；README 全景节没有图或树不合格，视图堆满同样不合格
- 不强行拆层级——简单目录硬拆「功能 1 / 功能 2」是仪式复杂度
