# 前端领域指南

当本 slice 含 UI 改动时，在 5a Scope Lock 和 5c 实现中纳入以下维度。

## 组件架构

- **单一职责**：一个组件做一件事。逻辑超出"渲染 + 本地交互"时，拆出 hook / 容器 / 纯函数。
- **展示 vs 容器**：把数据获取/状态管理与纯渲染分开，纯渲染组件更易测、易复用。
- **可组合优先于可配置**：宁可暴露 children/slot 让调用方组合，也不要堆叠十几个 boolean prop。
- **状态就近**：状态放在需要它的最近公共祖先，不无脑提到全局。
- **Props 契约清晰**：明确必填/可选、类型、默认值；默认值遵循 safe defaults（新行为默认关闭）。

## 无障碍（a11y）

- 用**语义化元素**（`button` / `nav` / `main` / `label`），不要用 `div` 模拟可交互控件。
- 交互元素**键盘可达**：Tab 可聚焦、Enter/Space 可触发、焦点顺序合理。
- 非文本内容给**替代文本**（`alt` / `aria-label`），图标按钮必须有可读名称。
- 颜色不是唯一信息载体；正文对比度满足 WCAG AA（4.5:1）。
- 动态内容变化用 `aria-live` 通知，模态聚焦管理（focus trap + 关闭返回触发元素）。

## 设计系统

- **用 token，不写魔法值**：颜色/间距/字号/圆角/阴影走设计系统变量，不硬编码 `#3b82f6` / `13px`。
- **复用现有组件**：先查组件库有没有现成的，不重复造 Button/Input/Modal。
- 新增样式遵循既有命名与分层约定（utility / BEM / CSS-in-JS，跟项目走）。
- 间距/排版用系统的 scale（如 4px/8px 栅格），不随手取值。

## 响应式

- **移动优先**：默认样式针对小屏，用 `min-width` 媒体查询向上增强。
- 用项目既定**断点 token**，不自创断点数值。
- 布局优先用 Flex/Grid 的内在响应能力（`flex-wrap` / `auto-fit` / `minmax`），减少硬媒体查询。
- 触控目标 ≥ 44×44px；避免仅 hover 才能触发的关键交互（触屏没有 hover）。
- 图片/媒体自适应（`max-width:100%` / `srcset`），避免溢出和布局抖动。

## 测试要点（配合 test-pyramid-guide）

- 组件单元测试：渲染输出 + 交互行为（点击/输入触发的状态变化），优先 unit 层。
- 用面向用户的查询（按角色/标签文本找元素），不依赖实现细节（class 名/DOM 结构）。
- 涉及路由/数据获取的整体流程才升 integration/e2e。
