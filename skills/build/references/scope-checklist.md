# Scope Lock 检查清单

5a 阶段逐项过一遍。任一项不满足 → 不进入 5b，先处理。

## 取 task

- [ ] 从计划取**一个** task（不是一批）
- [ ] task 改动的文件 **≤ 5 个**——超过说明粒度太粗，回 Plan 拆分
- [ ] task 带**可检验的验收标准**（能写成测试断言的那种，不是"做得好一点"）
- [ ] 这个 task 的前置依赖（其他 task）已完成

## Source check（来源核对）

- [ ] 实现前已 Read 所有涉及的现有代码
- [ ] 用到的框架/库 API 已查官方文档或读本地源码
- [ ] 每个关键判断都有来源标注：`[Read path:line]` / `[Doc URL]` / `[推断]`
- [ ] 文档不可达的，已标 `UNVERIFIED` 并退回本地源码，明说"离线降级"
- [ ] 没有把 `[推断]` 伪装成事实陈述

## Simplicity check

- [ ] 选了能满足验收标准的**最简**实现
- [ ] 没有为"将来可能需要"提前加抽象 / 配置 / 扩展点
- [ ] 没有引入计划里没提的新依赖

## Scope Discipline

- [ ] 只动本 task 声明的文件
- [ ] 发现的计划外问题已**记下来**（不顺手改）
- [ ] 没有"既然在这了顺便重构一下"的越界改动

## UI / 前端（仅当本 task 含 UI 改动）

- [ ] 已参考 `frontend-guide.md`
- [ ] 组件边界、无障碍、设计系统 token、响应式断点都纳入考量

## 出口自检

完成后，能用一句话回答：

> 本 slice 改 **____**（哪几个文件），验收标准是 **____**，依据是 **____**（来源）。

答不出 = Scope 没锁定，回到上面缺的那项。
